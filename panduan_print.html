1. Spesifikasi & Arsitektur Sistem

Aplikasi ini dibangun menggunakan arsitektur modern berbasis web dengan teknologi:

  • Framework: Next.js 16 (App Router), React 19, TypeScript 5.
  • ORM & Database: Prisma ORM v6 dengan dukungan Hybrid Database (otomatis beralih antara SQLite bawaan dan PostgreSQL Cloud).
  • Keamanan: JWT Cookie HttpOnly, Bcrypt Password Hashing, Cloudflare Turnstile Anti-bot, dan otorisasi hak akses bertingkat (Superadmin, Admin Instansi, Pegawai).

Penyimpanan (Storage) 3 GB SSD 10 GB SSD
Protokol Jaringan HTTP (Lokal Pengujian) Wajib HTTPS (SSL Aktif) agar GPS & Biometrik HP berfungsi

🔑 Format Serial Number Lisensi Resmi
Serial number memiliki format baku: TUKIN-PRO-XXXX-XXXX-XXXX (Contoh: TUKIN-PRO-9842-7105-3381).

Cara Melakukan Aktivasi Lisensi PRO di Aplikasi:

  1. Buka browser dan login ke aplikasi sebagai Super Admin.
  2. Buka menu samping: Super Admin → Pengaturan Sistem / Lisensi.
  3. Pada formulir Serial Number Lisensi, masukkan kode serial number PRO Anda.
  4. Klik tombol Aktivasi Lisensi.
  5. Sistem langsung memvalidasi checksum keamanan dan status lisensi akan berubah menjadi PRO (Aktif) seketika. Seluruh fitur Cloud Backup, Restore, dan Biometrik langsung terbuka.

4. Panduan Instalasi di VPS Linux (Ubuntu / Debian)

Instalasi di VPS merupakan metode terbaik agar aplikasi berjalan 24 jam non-stop dengan performa maksimal.

Metode Otomatis 1-Klik (Script vps-install.sh)

Anda cukup mengunggah folder aplikasi ke VPS lalu menjalankan satu perintah script berikut:

cd /opt/ekinerja
chmod +x vps-install.sh
bash vps-install.sh
⚡ Apa yang Dikerjakan Otomatis oleh Script Ini?
  • Memeriksa dan menginstal Node.js 20 LTS jika VPS masih baru.
  • Menginstal Process Manager PM2 sehingga aplikasi berjalan terus di background meskipun terminal SSH ditutup.
  • Menginstal dependensi via npm ci dan mensinkronkan database Prisma.
  • Membangun bundle produksi npm run build.
  • Mendaftarkan aplikasi ke startup sistem Linux (otomatis hidup jika VPS direstart).
  • Memasang jadwal Cron Job backup Google Drive harian setiap pukul 00:00 WIB.

Konfigurasi Nginx & SSL HTTPS (Wajib untuk GPS & Biometrik)

# 1. Install Nginx & Certbot
sudo apt install -y nginx certbot python3-certbot-nginx

# 2. Konfigurasi Nginx (/etc/nginx/sites-available/ekinerja)
server {
    listen 80;
    server_name kinerja.desa.id;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}

# 3. Aktifkan dan pasang SSL Gratis:
sudo ln -s /etc/nginx/sites-available/ekinerja /etc/nginx/sites-enabled/
sudo systemctl restart nginx
sudo certbot --nginx -d kinerja.desa.id

5. Panduan Instalasi di Web Hosting (cPanel)

Jika instansi menggunakan Web Hosting cPanel yang memiliki fitur Setup Node.js App (CloudLinux Passenger):

  1. Kompresi File: Kompres folder aplikasi ke aplikasi.zip (tanpa menyertakan folder node_modules dan .next).
  2. Upload ke cPanel: Buka cPanel File Manager, upload file ZIP ke folder di luar public_html (misal: /home/user/app-ekinerja), lalu klik Extract.
  3. Setup Node.js App di cPanel:
    • Node.js version: Pilih versi 18.x atau 20.x.
    • Application mode: Pilih Production.
    • Application root: Isi nama folder (misal: app-ekinerja).
    • Application startup file: Isi dengan server.js.
    • Klik Create.
  4. Install & Build via Terminal cPanel: 
    # Masuk virtual environment cPanel (salin dari halaman Node.js app):
source /home/user/nodevenv/app-ekinerja/20/bin/activate && cd /home/user/app-ekinerja

# Install & Build:
npm install --omit=dev
npm run build
  5. Klik tombol Restart pada aplikasi Node.js Anda di cPanel.

6. Konfigurasi Database (SQLite Bawaan vs PostgreSQL Cloud)

A. Menggunakan SQLite Bawaan (Nol Biaya & Praktis)

Kosongkan DATABASE_URL="" di file .env. Seluruh data otomatis tersimpan di storage/database.sqlite. Mode ini langsung bekerja tanpa konfigurasi server database tambahan.

B. Menggunakan PostgreSQL Cloud (Contoh: Sumopod / Supabase)

Sistem aplikasi otomatis mendeteksi jika URL diawali dengan postgresql:// atau postgres://.

💡 Petunjuk Penting Khusus Sumopod (Sesuai Dashboard Sumopod):
Pada dashboard Sumopod terdapat 3 tab koneksi:
1. Transaction Pooler (Port 6432)
2. Session Pooler
3. Direct Connection (Port 5432)

Sangat Disarankan: Pilih tab Direct Connection (Port 5432). Prisma ORM dan proses pembuatan tabel otomatis (npx prisma db push) berjalan paling stabil melalui Direct Connection tanpa kendala pooling PgBouncer.

Contoh Connection String yang disalin ke .env:

DATABASE_URL="postgresql://uazuSleyutH953G5A.jkt1_003:b56aabd50b51c19d747f830f@pgsql-dbas-jkt1-003.sumobase.my.id:5432/db658b2889efac70aa"

Perintah Sinkronisasi & Pembuatan Tabel:

  • Untuk PostgreSQL Cloud (Sumopod/Supabase): npx prisma db push
  • Untuk SQLite Bawaan: SQLITE_DATABASE_URL="file:./storage/database.sqlite" npx prisma db push --schema=prisma/schema.sqlite.prisma
  • Atau gunakan wizard interaktif: node setup-db.js

7. Panduan Migrasi Database dari SQLite ke Cloud (Sumopod/Supabase)

Jika pada awalnya aplikasi berjalan menggunakan SQLite lokal dan sudah memiliki data (pegawai, absensi, kegiatan), Anda dapat memindahkan seluruh data tersebut ke Sumopod/Supabase secara utuh tanpa kehilangan 1 data pun:

1. SQLite Aktif
Unduh File Backup JSON dari Superadmin
2. Update .env
Isi DATABASE_URL Sumopod
3. Sinkron Tabel
Jalankan npx prisma db push
4. Restore JSON
Pulihkan Database di Web Superadmin

Langkah-Langkah Praktis Migrasi:

  1. Unduh Cadangan Lengkap:
    Saat aplikasi masih memakai SQLite, buka web browser dan login sebagai Super Admin.
    Buka menu Super Admin → Kelola Database (`/superadmin/database`).
    Pada kartu *Export & Backup Database*, klik tombol 📥 Unduh Backup (.json) dan simpan file di laptop Anda.
  2. Ganti URL di File .env:
    Buka file .env di server Anda, ubah baris DATABASE_URL menjadi Connection String dari Sumopod: 
    DATABASE_URL="postgresql://uazuSleyutH953G5A.jkt1_003:b56aabd50b51c19d747f830f@pgsql-dbas-jkt1-003.sumobase.my.id:5432/db658b2889efac70aa"
  3. Inisialisasi Tabel di Sumopod:
    Buka terminal VPS di folder aplikasi lalu jalankan: 
    npx prisma db push
    (Dalam beberapa detik seluruh tabel otomatis terbuat di server Sumopod).
  4. Restart Aplikasi:
    Jalankan perintah: pm2 restart tukin-pamong (atau klik restart di cPanel).
  5. Pulihkan Data ke Database Baru:
    Buka kembali web browser, login sebagai Super Admin, masuk ke menu Kelola Database.
    Di bagian Restore / Pemulihan Database, klik Pilih File Backup (.json) dan pilih file yang diunduh pada Langkah 1 tadi.
    Klik Pulihkan Database.
    Selesai! Seluruh data pegawai, presensi, aktivitas, dan master data sudah berpindah dan aktif di Sumopod.

8. Panduan Auto-Backup Google Drive (Fitur PRO)

Fitur ini otomatis mencadangkan seluruh data setiap malam pukul 00:00 WIB ke Google Drive Anda dengan retensi otomatis 7 hari.

A. Pengambilan Kredensial OAuth2 Google:

  1. Buka Google Cloud Console → Buat project baru → Aktifkan Google Drive API.
  2. Di menu Credentials, buat OAuth Client ID tipe Web Application dengan Authorized redirect URI: https://developers.google.com/oauthplayground. Catat Client ID & Client Secret.
  3. Buka OAuth 2.0 Playground → Masukkan Client ID & Secret di menu gerigi ⚙️.
  4. Pilih scope https://www.googleapis.com/auth/drive → Klik Authorize APIs → Login akun Google Anda.
  5. Klik Exchange authorization code for tokens dan salin Refresh Token.

B. Konfigurasi di Halaman Super Admin Database:

  1. Login Super Admin → Buka Kelola Database → Klik ⚙️ Pengaturan Google Drive & Cron.
  2. Masukkan Client ID, Client Secret, dan Refresh Token.
  3. Pemilih Folder Interaktif: Klik tombol 📂 Pilih Folder. Sistem akan membaca Google Drive Anda dan menampilkan daftar folder. Anda bisa memilih folder tujuan atau memilih 🏠 My Drive (Root).
  4. Klik 🔍 Uji Koneksi Google, lalu klik Simpan Pengaturan.
  5. Tekan tombol ☁️ Backup Sekarang ke Drive untuk melakukan pengujian langsung.

9. Panduan Restart, Pemeliharaan & Troubleshooting

A. Daftar Perintah Restart Berdasarkan Lingkungan:

Lingkungan Cara Restart Keterangan
VPS Linux (PM2) pm2 restart tukin-pamong Aplikasi restart dalam 1-2 detik, tetap jalan di background.
VPS Zero-Downtime Reload pm2 reload tukin-pamong Digunakan setelah update kode tanpa mengganggu user aktif.
cPanel Hosting Klik tombol Restart pada menu Setup Node.js App Melalui antarmuka grafis cPanel.
Terminal Manual (Dev) Tekan Ctrl + C lalu jalankan bash start.sh Mode pengujian lokal.

B. Perintah Penting Manajemen PM2 di VPS:

# Melihat status dan penggunaan RAM/CPU:
pm2 status

# Melihat log aktivitas sistem secara langsung (live output):
pm2 logs tukin-pamong

# Melihat 150 baris log error terakhir:
pm2 logs tukin-pamong --err --lines 150

# Menghentikan sementara aplikasi:
pm2 stop tukin-pamong

# Menyalakan kembali aplikasi:
pm2 start tukin-pamong

C. Panduan Troubleshooting Masalah Umum:

1. Masalah: Port 3000 Bentrok (Port already in use)
Jika aplikasi tidak bisa menyala karena port 3000 sedang terkunci oleh proses lain: 
sudo lsof -i :3000
# Matikan proses tersebut:
sudo kill -9 <PID_ANGKA>
pm2 restart tukin-pamong
2. Masalah: "Permission denied" pada file SQLite
Jika menggunakan SQLite bawaan dan muncul error izin tulis pada folder storage: 
chmod -R 775 storage/
3. Masalah: GPS Presensi dan Biometrik Tidak Muncul di HP
Browser smartphone memblokir akses sensor GPS dan WebAuthn jika koneksi belum menggunakan HTTPS.
Solusi: Pastikan domain telah memiliki sertifikat SSL aktif (jalankan sudo certbot --nginx di VPS).
